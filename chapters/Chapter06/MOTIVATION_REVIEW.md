# বাস্তব সমস্যা থেকে ধারণা — সম্পাদনা পরিকল্পনা

## বর্তমান নির্দেশনা

শিক্ষার্থী যেন সমস্যা, কারণ, প্রয়োজনীয় সক্ষমতা, ধারণাটির কাজের পদ্ধতি ও বাস্তব ব্যবহার বুঝতে পারে। ২০২৬-০৯-৩০-এর নতুন নির্দেশে বোঝার সুবিধার জন্য কিছু পৃষ্ঠা বাড়ানো অনুমোদিত; আগের ১৪০ পৃষ্ঠা এখন কঠোর সর্বোচ্চ সীমা নয়। পুরোনো তথ্য, উদাহরণ ও কোড বাদ যাবে না।

- বিদ্যমান পরিচিত উদাহরণকে আগে ব্যবহার; একই গল্পের অনুলিপি নয়।
- নতুন গল্প সংক্ষিপ্ত ও সম্ভাব্য বাস্তব পরিস্থিতিভিত্তিক; নির্দিষ্ট প্রতিষ্ঠানের প্রকৃত ব্যবস্থা বা প্রযুক্তি আবিষ্কারের ইতিহাস দাবি নয়।
- সমস্যা → কী সক্ষমতা প্রয়োজন → কীভাবে সমাধান → ব্যবহার/ফল; প্রয়োজনে সীমা ও বিপরীত উদাহরণ।
- মূল সিলেবাস অপরিবর্তিত। Attached suggestion-এর Normalization বা আলাদা Web Database topic আমদানি নয়; website/customer/social-media প্রয়োগ মূল পাঠের ভেতরেই থাকবে।
- পরিচিত dataset ও আগের সব SQL/output সংরক্ষিত। Native visual কেবল যেখানে কারণ বোঝায়; প্রতিটি subsection-এ একই flow/box নয়।

## Topic coverage

| পাঠ | সমস্যার প্রেক্ষিত ও শেখার লক্ষ্য |
|---|---|
| Data/Database | কলেজের ছড়ানো যোগাযোগের তথ্য → একটি নির্ভরযোগ্য সংগঠিত উৎস |
| Field/Record/Table | একই ঘরে নাম-ফোন-ফল → তুলনা ও পৃথক হালনাগাদের জন্য নির্দিষ্ট কলাম |
| DBMS | ওয়েবসাইটের customer/order record → নিয়ন্ত্রিত যৌথ ব্যবহার |
| RDBMS/Keys | গ্রাহকের বহু ক্রয়; নাম দিয়ে ভুল ব্যক্তির সংশোধন → key-ভিত্তিক পরিচয় ও সম্পর্ক |
| Creation | হাসপাতালের রোগী বনাম প্রতি সাক্ষাৎ → উদ্দেশ্য অনুযায়ী কাঠামো |
| Data Type | দাম Text ও ফোন Number → হিসাব/পরিচিতির উপযুক্ত ধরন |
| Query | বকেয়া ফি নির্ণয় → সারির শর্ত, নির্বাচিত কলাম, হালনাগাদ উৎস |
| Sorting | পূর্ণ ফলের তালিকা থেকে নির্দিষ্ট প্রদর্শনক্রম; record-এর মান অপরিবর্তিত |
| Indexing | ব্যাংক হিসাব ঘন ঘন খোঁজা → সহায়ক search structure; query result নয় |
| Relationship | বিদ্যমান Rahim ambiguity/junction ব্যাখ্যায় হাসপাতাল ও ব্যাংক প্রয়োগের সংযোগ |
| Corporate/CRM | অভিযোগ, order, delivery তথ্য বিচ্ছিন্ন → অনুমতি অনুযায়ী সমন্বিত সেবা |
| Government | নাগরিককে আবেদন খুঁজতে বারবার আসতে হয় → ApplicationID দিয়ে অবস্থা অনুসরণ |
| Data/System Security | ফাঁস, অবৈধ পরিবর্তন, হারানো; বৈধ login বনাম সীমিত অধিকার |
| Encryption | অননুমোদিত হাতে চলে যাওয়া ফলপত্র → উপযুক্ত key ছাড়া অপ্রকাশ্য রূপ |
| Transaction/ACID | বিদ্যমান bank transfer-এ সম্পূর্ণতা, বৈধতা, concurrency, স্থায়িত্বের প্রয়োজন |
| NoSQL | ভিন্ন পণ্যবিবরণ ও সামাজিক সংযোগের ভিন্ন query → উপযুক্ত model |
| Big Data | ওয়েবসাইটের activity থেকে চাহিদা → যাচাই, বিশ্লেষণ ও সিদ্ধান্ত; বেশি data মানেই সত্য নয় |
