# Chapter 6 — বাংলা ভাষা ও পরিভাষার রীতি

## মূল নীতি

বাংলা বাক্যের গঠন স্বাভাবিক থাকবে। পরিচিত কারিগরি পরিভাষা প্রয়োজনমতো ইংরেজিতে থাকবে; SQL, ফিল্ড/টেবিলের প্রকৃত নাম, মান, সূত্র ও সফটওয়্যারের বোতামের নাম বদলাবে না। প্রথম সংজ্ঞা বা শিরোনামে বাংলা নামের সঙ্গে ইংরেজি পরিভাষা রাখা যায়। পরের ব্যাখ্যায় বারবার দুই ভাষায় একই নাম লেখার প্রয়োজন নেই।

ব্যবহারকারীর সর্বশেষ নির্দেশ অনুযায়ী এই ভাষা-সম্পাদনায় কোনো ধারণা, তথ্য, উদাহরণ বা ব্যাখ্যা বাদ দেওয়া কিংবা সংক্ষেপ করা যাবে না। দীর্ঘ বাক্যকে ছোট বাক্য বা একাধিক অনুচ্ছেদে সাজানো যাবে; মূল বক্তব্যের প্রতিটি অংশ, প্রসঙ্গ ও শর্ত রাখতে হবে। পৃষ্ঠাসংখ্যা কমানোর জন্য তথ্য ছাঁটা যাবে না।

| পরিভাষা | সাধারণ ব্যাখ্যায় ব্যবহার |
|---|---|
| Database / Data / Information | ডেটাবেজ / ডেটা / তথ্য |
| Raw Data / Processing | কাঁচা ডেটা (Raw Data) / প্রক্রিয়াকরণ (Processing); প্রথম ধারণা-পরিচয়ে ইংরেজি নামও থাকবে |
| Table / Field / Record | টেবিল / ফিল্ড / রেকর্ড |
| Row / Column / Value | সারি / কলাম / মান |
| Query / Condition | কুয়েরি / শর্ত |
| Sorting / Indexing / Index | সর্টিং / ইনডেক্সিং / ইনডেক্স |
| Relationship | সম্পর্ক; Relation-এর টেবিল অর্থের সঙ্গে মেশানো যাবে না |
| Primary Key / Foreign Key | প্রাইমারি কী / ফরেন কী; তুলনা ও কী চিহ্নিত করার স্থানে ইংরেজি নামও রাখা যায় |
| Parent Table / Child Table | প্রথম পরিচয়ে ব্যাখ্যাসহ ইংরেজি নাম; পরে প্রয়োজনমতো ব্যবহার |
| Transaction / Normalization | ট্রানজেকশন / নরমালাইজেশন |
| Encryption / Decryption | এনক্রিপশন / ডিক্রিপশন |
| Authentication / Authorization | পরিচয় যাচাই / কাজের অনুমতি নির্ধারণ; প্রথম পরিচয়ে ইংরেজি নাম |
| User / File / Software | ব্যবহারকারী / ফাইল / সফটওয়্যার |
| Big Data / Web Database | বিগ ডেটা / ওয়েব ডেটাবেজ |

Data-এর সংজ্ঞা ও শিরোনামে সিলেবাসের পরিচিত বাংলা নাম “উপাত্ত” থাকবে। সাধারণ ব্যাখ্যায় “ডেটা” প্রাধান্য পাবে। Student, Result, Name, Roll, Salary, Balance, Department ইত্যাদি উদাহরণের প্রকৃত identifier; এগুলো অনুবাদ করা যাবে না। Data Type, Field Size, SQL View, Query Design-এর মতো পরিভাষা ও interface label প্রসঙ্গ অনুযায়ী অক্ষত থাকবে।

ব্যবহারকারীর সর্বশেষ পরিভাষা-নির্দেশ অনুযায়ী পরিচিত ইংরেজি নাম ধারণা চেনা ও পরীক্ষার ভাষার সঙ্গে মিল করতে সাহায্য করলে তা রাখতে হবে। Raw Data, Data Value, Metadata, Data Dictionary, System Catalog ও Data Independence-এর মতো নির্দিষ্ট নাম প্রথম ব্যাখ্যায় বাংলার পাশে থাকবে। DBMS ও RDBMS-এর পূর্ণ ইংরেজি নামও পরিচয়ের সময় দিতে হবে। সাধারণ বাংলা বাক্য ইংরেজি সাধারণ বিশেষ্য দিয়ে ভরে ফেলার প্রয়োজন নেই।

## বাক্য, অনুচ্ছেদ ও উদাহরণ

- এক বাক্যে একটি মূল বক্তব্য; একই অনুচ্ছেদে ঘনিষ্ঠভাবে সম্পর্কিত ২–৫টি বাক্য। বাক্য কঠিন হলে ভাঙতে হবে, শুধু শব্দসংখ্যা মেলানোর জন্য নয়।
- উদাহরণের শুরুতে পরিস্থিতি ও প্রয়োজন, পরে ব্যবহৃত মান/শর্ত, শেষে ফলের কারণ বোঝাতে হবে। “ধরা যাক”, “এখানে”, “তাই”, “ফলে” স্বাভাবিক সংযোগে ব্যবহার করতে হবে।
- বিষয় পরিচয়ের স্বাভাবিক ধারা হবে: বাস্তব সমস্যা → সমস্যার প্রভাব → সমাধানের প্রয়োজন → সংজ্ঞা → সহজ ব্যাখ্যা → উদাহরণ। সব উপাদানের জন্য আলাদা বক্স বাধ্যতামূলক নয়; অনুচ্ছেদের মধ্যেও যোগসূত্র পরিষ্কার রাখা যাবে। পূর্বধারণার পরিচয় দেওয়ার আগে তার ওপর নির্ভরশীল বিস্তারিত আলোচনা শুরু করা যাবে না।
- SQL-এর নির্দেশ অপরিবর্তিত থাকবে। আশপাশের বাক্যে কী চাওয়া হয়েছে এবং ফলটি কেন এসেছে তা সহজ বাংলায় বলতে হবে।
- ব্যাখ্যা অনুচ্ছেদে; সমান্তরাল বৈশিষ্ট্য, ধাপ ও তালিকা বুলেটে। আলাদা আলাদা অসম্পূর্ণ বাক্যে উদাহরণ ছড়িয়ে দেওয়া যাবে না।
- বাংলা বাক্যের শেষে দাঁড়ি; SQL/ফাইলের নাম/গাণিতিক রাশিতে প্রয়োজনীয় মূল চিহ্ন বজায় রাখতে হবে।
- “সব”, “সাধারণত”, “পারে”, “শুধু”, “অন্তত”, “সর্বোচ্চ”, “NULL” ইত্যাদির শর্তগত অর্থ বদলানো যাবে না।
- Mahbubur Rahman ও OkkhorPattro থেকে পরিষ্কার ব্যাখ্যা ও ধাপে ধাপে প্রয়োগের সাধারণ শিক্ষণরীতি শেখা হবে; বাক্য বা উদাহরণ নকল করা হবে না।

## বিষয়ভিত্তিক যাচাই

প্রতিটি পাঠে অর্থ সংরক্ষণ → ভাষা সম্পাদনা → অনুচ্ছেদ/বিন্যাস যাচাই। প্রতিটি সম্পাদিত পাঠের পরে LaTeX compile ও overflow পরীক্ষা; শেষে SQL, table values, diagram, সূত্র ও প্রশ্নসংখ্যা মিলিয়ে দেখা হবে। সংজ্ঞা, উদাহরণ বা পরীক্ষাসংশ্লিষ্ট তথ্য বাদ দিয়ে ভাষা ছোট করা যাবে না।

## শিরোনাম ও অক্ষরের গুরুত্ব

Chapter 6-এর দৃশ্যমান রীতি `latex/visual_style.tex`-এ এক জায়গায় নির্ধারিত থাকবে। কোনো একটি topic-এ আলাদা রং বা অক্ষরের আকার বসিয়ে একই স্তরের শিরোনামকে ভিন্ন দেখানো যাবে না। বর্তমান রীতি:

| স্তর | অক্ষরের আকার | রং ও গুরুত্ব | আগে / পরে ফাঁক |
|---|---|---|---|
| `\section` | `\Large` | গাঢ় teal `#14667A`, bold | 6pt / 3pt |
| `\subsection` | `\large` | একই teal, bold | 5pt / 2pt |
| `\subsubsection` | 13pt, 15pt line height | rose `#9C3658`, bold | 4pt / 2pt |

Kalpurush-এর পৃথক bold face পাওয়া যাচ্ছে না বলে এই অধ্যায়ের স্থানীয় font family-তে regular-এর জন্য `FakeBold=1.25` এবং bold-এর জন্য `FakeBold=2.4` নির্ধারিত হয়েছে। এর উদ্দেশ্য বাংলা সাধারণ লেখা ও অর্থবহ bold লেখার দৃশ্যমান পার্থক্য রাখা। এই ব্যবস্থা Chapter 6-এর group-এর মধ্যে থাকবে; অন্য অধ্যায়ের font বদলাবে না। এই font একই Kalpurush ব্যবহার করে; আলাদা native bold face আছে—এমন দাবি করা যাবে না।

স্থানীয় font family-এর সংজ্ঞা `latex/text_font.tex`-এ রাখা হয়েছে। `visual_style.tex` এবং standalone সূচিপত্র একই সংজ্ঞা ব্যবহার করবে, যাতে সূচিপত্রেও bold-shape substitution না হয়।

প্রকৃত নতুন উপবিষয়ের পরিচয় `\subsubsection` হবে। একই অনুচ্ছেদের কয়েকটি সমান্তরাল কাজ বোঝাতে ছোট bold নাম ব্যবহার করা যাবে। `ব্যাখ্যা:`, `কখন ব্যবহার করবে?` বা উদাহরণের পাশে `ফল`-কে প্রতিবার নতুন numbered heading করতে হবে না। গুরুত্বপূর্ণ term, শর্ত এবং ভুলের মূল জায়গায় bold থাকবে; সম্পূর্ণ দীর্ঘ বাক্য বা অনুচ্ছেদ bold করা যাবে না।

## সংজ্ঞা, পূর্ণ নাম ও বক্স

- গুরুত্বপূর্ণ ধারণার প্রথম যথাযথ পরিচয়ে একটি `definitionbox` থাকবে। সাধারণত ১–৩টি বাক্যে পরীক্ষায় লেখার উপযোগী সংজ্ঞা দেবে; কারণ, প্রয়োগ, উদাহরণ ও সীমাবদ্ধতার সম্পূর্ণ ব্যাখ্যা পরের অনুচ্ছেদে থাকবে। দীর্ঘ ব্যাখ্যা বক্সের বাইরে সরানো মানে তা বাদ দেওয়া নয়।
- সংজ্ঞার শিরোনামে বাংলা নাম ও পরিচিত ইংরেজি নাম রাখা হবে। SQL keyword, statement বা clause-এর নাম তাদের প্রচলিত মূল রূপে থাকবে। একই সংজ্ঞা পরে আবার নতুন definitionbox-এ লেখা হবে না; আগের ধারণার সংক্ষিপ্ত স্মরণ ও উপযুক্ত reference ব্যবহার করবে, কিন্তু স্বতন্ত্র উদাহরণ ও যুক্তি রাখবে।
- প্রথম অর্থবহ ব্যবহারে সংক্ষিপ্ত রূপের পূর্ণ নাম পরিচিত করাতে হবে। DBMS, RDBMS, DBA, SQL, QBE, DDL, DML, DQL, DCL, TCL, ACID, PK, FK, AES, DES, RSA ও IDS বিশেষভাবে মিলিয়ে দেখতে হবে। Learning box-এ কোনো অপরিচিত সংক্ষিপ্ত রূপ আগে এলে সেখানেই পরিচয় দেবে।
- পূর্ণ নাম পরিচিত হওয়ার পরে সাধারণ ব্যাখ্যায় বারবার বড় বন্ধনী লিখতে হবে না। কোনো field-এর নাম বা data value ছোট নামে দেওয়া থাকলে তার অর্থ একটি ছোট ব্যাখ্যা বা legend-এ জানানো যায়; নামটি বদলানো যাবে না। SQL-এর `NULL`, `TOP`, `JOIN` বা `WHERE`-এর জন্য কৃত্রিম পূর্ণরূপ বানানো যাবে না। ISO-এর ক্ষেত্রে সংস্থার পূর্ণ নাম পরিচিত করবে; ISO-কে ইংরেজি নামের প্রথম অক্ষর দিয়ে তৈরি acronym বলবে না।
- `keypointbox` গুরুত্বপূর্ণ ধারণা বা মনে রাখার বিষয়; `mistakebox` ভুল ধারণা ও তার সঠিক ব্যাখ্যা; `boardbox` পরীক্ষার নির্দিষ্ট তথ্য বা সতর্কতা। প্রতিটি ছোট বক্তব্যের জন্য বড় বক্স বানানো যাবে না। পরিচিত বিভ্রান্তিতে প্রয়োজনমতো `ভুল ধারণা`, `কেন ভুল` এবং `সঠিক ধারণা` আলাদা করে বোঝানো হবে।

## সারণি, চিত্র ও পৃষ্ঠার বিন্যাস

সারণির কালো border, পাঠযোগ্য header, একই padding এবং লেখা বহুল ঘরে ragged-right alignment বজায় থাকবে। Code/output এবং ছোট table/explanation উপযুক্ত ক্ষেত্রে পাশাপাশি থাকবে। ব্যাখ্যার মধ্যে থাকা ছবির label ছোট থাকবে; বাংলা ব্যাখ্যা মূল লেখায় বা নিচে থাকবে। শুধু পৃষ্ঠা কমানোর জন্য অক্ষরের আকার অতিরিক্ত ছোট করা যাবে না।

প্রতিটি সম্পাদিত topic-এর পরে compile করে সংশ্লিষ্ট পৃষ্ঠা দেখতে হবে। নিচে একা পড়ে থাকা heading, সারণির পরে অপ্রয়োজনীয় ফাঁক, পাশাপাশি কলামের overlap এবং নিচে বেরিয়ে যাওয়া লেখা আগে ঠিক করে তারপর পরের topic-এ যেতে হবে। বিষয়বস্তুর স্পষ্টতা ও পাঠযোগ্যতাই প্রধান; ব্যবহারকারীর পরবর্তী নির্দেশ আগের ১৪৩ পৃষ্ঠার সীমা সরিয়েছে।

শেষে তিনটি পৃথক যাচাই থাকবে: বিষয়বস্তু সংরক্ষণ; বাংলা ভাষা ও প্রসঙ্গ; দৃশ্যমান বিন্যাস ও LaTeX। বর্তমান পর্বের snapshot, compile log, render ও preservation audit `build/chapter06_review/complete_audit/`-এ রাখা হবে। যান্ত্রিক সংরক্ষণ-পরীক্ষা বাংলা বাক্যের অর্থ পড়ার বিকল্প নয়।

পরবর্তী অতিরিক্ত পর্যালোচনার স্বতন্ত্র snapshot ও যাচাইয়ের রেকর্ড `build/chapter06_review/continuation_audit/`-এ থাকবে।
